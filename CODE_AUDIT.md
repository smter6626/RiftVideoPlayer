# CODE_AUDIT.md — Rift (SwiftUI / Metal macOS video player)

Generated by the `ios-code-audit` skill workflow, cross-checked with `swiftui-performance-audit`, `swift-concurrency-pro`, and `swift-security-expert`.

- **Target:** SwiftPM executable target `Rift` (macOS 14+), `Sources/Rift/`
- **LOC:** 24 Swift files, ~8,400 lines; 10 `.metal` files
- **Build ground truth:** `swift build` emits **0** compiler warnings and **0** concurrency warnings. Two build-configuration warnings only (see §4.1, §4.2).
- **Verification:** Every Critical/High finding below was opened and confirmed in the cited file.

The dead-code files it lists — `VideoInterpolationPipeline.swift`, `PlaceboRenderer.swift`, `VideoDecoderEngine.swift`, `LiquidGlassButton.swift` — and the `drawFramePlus`/`copyFrame`/`makeTexture`/`GlassCapsule`/`setApplicationIcon`/`isSeekingPreview` symbols **no longer exist in the tree** (verified 2026-08-28). ## 1. Executive summary

1. **[High] RIFE model-missing failure is swallowed, not surfaced** — `RIFECoreMLInterpolator.loadEngine()` returns without throwing when the model URL is nil, so the only signal is a 3s retry backoff with no user message. §5.1
2. **[High] HLS mirrored playlist write failures are discarded** — two `_ = Self.writeMirroredHLSPlaylist(...)` call sites ignore the `Bool` result, so a failed write serves a stale playlist. §5.5
3. **[High] `writeMirroredHLSPlaylist` itself swallows its write error** — the `catch` returns `false` with no logging; caller can't tell why. §5.8
4. **[High] Frame⁺ MEMC silently degrades to crossfade** — all four `encode*` sub-functions `guard` on a nil compute encoder and return, and the caller at `RiftPlayerView` returns `nil` with no feedback; GPU pipeline failure is invisible. §5.3 / §5.4
5. **[Medium] Multiple `catch {}` blocks return empty/zero silently** — FFprobe codec inspection, optical-flow, and cache-dir creation failures are dropped without logging or user visibility. §5.6 / §5.7 / §5.9
6. **[Low] Build emits two benign warnings** — an unhandled `.DS_Store` resource and a prohibited `-D_THREAD_SAFE` flag. §4.1 / §4.2

### 3.2 `RIFECoreMLInterpolator` is fully `@MainActor`
- **Location:** `Sources/Rift/RIFECoreMLInterpolator.swift:5`
- **What:** The interpolator and its `loadEngine()` run on the main actor; `MLModel.compileModel(at:)` is correctly offloaded via `Task.detached(priority: .userInitiated)`.

### 3.3 `FramePlusMEMCEngine` is non-isolated, used from the MTKView render callback
- **Location:** `Sources/Rift/FramePlusMEMCEngine.swift:4`, called at `RiftPlayerView.swift:628`
- **What:** The engine has no actor isolation but is only exercised from the `MTKView` delegate (single render thread). Cross-thread access is not currently possible, but the type offers no compile-time guarantee.
- **Why:** Latent risk if a future refactor calls `encode` from another context.
- **Action:** Document the single-thread contract on `encode(...)`, or annotate the class `@unchecked Sendable` with a comment if shared later.
- **Severity:** Medium

## 4. API modernity

### 4.1 Unhandled resource file warning
- **Location:** `Package.swift:21` (`.copy("Resources")`)
- **What:** `swift build` warns `found 1 file(s) which are unhandled` — caused by `Resources/.DS_Store`.
- **Why:** SwiftPM cannot classify `.DS_Store` as a processable resource.
- **Action:** Remove `.DS_Store`; optionally use `.process("Resources")` instead of `.copy` so the toolchain manages the directory.
- **Severity:** Low

### 4.2 Prohibited flag `-D_THREAD_SAFE`
- **Location:** Build log (`warning: prohibited flag(s): -D_THREAD_SAFE`)
- **What:** The toolchain injects `-D_THREAD_SAFE`, which newer SwiftPM forbids. Origin is the SwiftPM/toolchain, not `Package.swift`.
- **Why:** Harmless warning today, but may become an error in a future toolchain.
- **Action:** Track with a toolchain/SwiftPM upgrade; no source change available.
- **Severity:** Low

## 5. Bugs / logic errors

### 5.1 RIFE model-missing failure is swallowed (S2)
- **Location:** `Sources/Rift/RIFECoreMLInterpolator.swift:45-50`
- **What:** `loadEngine()` is `async throws`, but when `findBundledModelURL()` returns `nil` it sets `state = .unavailable` and **returns without throwing**. The caller (`loadRIFEIfNeeded`) never learns the model is absent.
- **Why:** The prior Frame⁺-bundle bug pattern: a missing/corrupt model produces no error, only an invisible retry backoff.
- **Action:** `throw RIFEError.modelLoad("RIFE model not found in bundle")` on the nil path so the caller can surface it via `statusMessage`.
- **Severity:** High

### 5.2 RIFE load error drops the underlying reason (S1)
- **Location:** `Sources/Rift/RiftPlayerView.swift:396-398`
- **What:** `catch { self.rifeFailureBackoffUntil = ... + 3.0 }` discards `error` and shows no user-facing message.
- **Why:** User gets a silent 3s backoff with no explanation of why interpolation is unavailable.
- **Action:** Capture `error` and set `state.statusMessage` (the existing user-facing channel, `PlayerState.swift:37`) with the localized reason; keep the backoff.
- **Severity:** Medium

### 5.3 Frame⁺ MEMC encode sub-functions silence encoder failure (S4)
- **Location:** `Sources/Rift/FramePlusMEMCEngine.swift:169, 179, 190, 200`
- **What:** Each `encode*(...)` does `guard let encoder = commandBuffer.makeComputeCommandEncoder() else { return }`. A nil encoder aborts the whole GPU pass mid-way with no signal, and `encode(...)` still throws nothing.
- **Why:** If encoder creation ever fails, motion interpolation silently degrades to crossfade — the exact failure mode the prior audit called out, still unhandled.
- **Action:** Propagate encoder failure upward: have the `encode*` functions throw `FramePlusMEMCError.encoder`, and `encode(...)` re-throw so the caller can log and surface it.
- **Severity:** High

### 5.4 MEMC encode caller swallows the thrown error (S3)
- **Location:** `Sources/Rift/RiftPlayerView.swift:627-637`
- **What:** `try framePlusEngine.encode(...)` is wrapped in `catch { return nil }` — no logging, no user feedback.
- **Why:** Even after fixing §5.3 to throw, this catch would still hide it.
- **Action:** Log the error and set a transient `statusMessage` (e.g. "Frame⁺ interpolation unavailable"); fall back to crossfade only as a deliberate, visible degradation.
- **Severity:** Medium

### 5.5 HLS mirrored playlist write result discarded (S5)
- **Location:** `Sources/Rift/PlayerState.swift:1504, 1620`
- **What:** `_ = Self.writeMirroredHLSPlaylist(...)` ignores the `Bool` return at two call sites.
- **Why:** If the write fails, a stale playlist is served to the HLS server and playback breaks with no symptom.
- **Action:** Check the `Bool`; on `false`, set `hlsPlaybackURL = nil` and surface "HLS playlist update failed".
- **Severity:** High

### 5.6 Cache directory creation failure is silent (S6)
- **Location:** `Sources/Rift/PlayerState.swift:765-775`
- **What:** `ensureCompatibleVideoCacheDirectoryExists` returns `false` on `catch` with no logging.
- **Why:** A failed cache directory means compatible-mode transcoding writes nowhere; the user sees "Switching to compatible mode…" then nothing.
- **Action:** Log the underlying `error` at least in debug builds; consider surfacing a one-time warning.
- **Severity:** Medium

### 5.7 FFprobe codec inspection swallows failure (S7)
- **Location:** `Sources/Rift/PlayerState.swift:890-892`
- **What:** `inspectCodecs` `catch { return [] }` — a crashed/missing ffprobe yields an empty track list with no error.
- **Why:** User sees no audio/subtitle options and no explanation; debugging is blind.
- **Action:** Log the `error` and the ffprobe path; if `findFFprobe()` is nil, `inspectCodecs` already returns `[]` at line 839 — add a `statusMessage` there too (see §5.10).
- **Severity:** Medium

### 5.8 `writeMirroredHLSPlaylist` swallows its write error (S8)
- **Location:** `Sources/Rift/PlayerState.swift:1726-1733`
- **What:** The `catch` returns `false` without recording why the `write(to:atomically:)` failed.
- **Why:** Callers (§5.5) can't distinguish "disk full" from "permission denied"; the failure is invisible end-to-end.
- **Action:** Log `error.localizedDescription` before returning `false` (keep the `Bool` contract).
- **Severity:** High

### 5.9 Optical-flow failure silently clears the flow (S9)
- **Location:** `Sources/Rift/OpticalFlowEngine.swift:111-115`
- **What:** `catch { self.latestFlow = nil }` drops the `VNGenerateOpticalFlowRequest` error.
- **Why:** Motion-estimation failure is invisible; downstream interpolation silently falls back.
- **Action:** Log the `error` (guarded by the existing lock) so a persistent Vision failure is diagnosable.
- **Severity:** Medium

### 5.10 Missing ffprobe yields silent `nil` duration (S10)
- **Location:** `Sources/Rift/PlayerState.swift:895-896` (`inspectDuration`), `2090` (`findFFprobe`)
- **What:** `inspectDuration` returns `nil` when `findFFprobe()` is nil, and the caller treats duration as unknown with no warning.
- **Why:** A missing ffprobe dependency makes duration-based UI (scrubber, HLS reveal math) silently wrong.
- **Action:** When `findFFprobe()` returns nil, set `statusMessage` once: "ffprobe not found — duration/codec info limited".
- **Severity:** Medium

## 7. Performance

### 7.1 Per-frame `try?` allocations in the render path
- **Location:** `Sources/Rift/RiftPlayerView.swift` (draw/decode helpers)
- **What:** Multiple `try? FileManager.default…` / `try? String(contentsOf:)` style calls appear in playback-adjacent code paths; the hot `drawFrame`/`interpolate` path itself uses Metal/CI and avoids them.
- **Why:** Per the `swiftui-performance-audit` code-smells guidance, main-thread I/O in hot paths spikes CPU; here it is mostly in setup/HLS polling, not per-frame, so impact is low.
- **Action:** Keep file I/O off the render frame; acceptable as-is.
- **Severity:** Low

### 7.2 Broad `@Published` observation of `statusMessage`
- **Location:** `Sources/Rift/PlayerState.swift:37`, `ContentView.swift:517`
- **What:** `statusMessage` is a single optional string on the central observable; frequent updates can re-evaluate `ContentView` body.
- **Why:** Minor invalidation fan-out; only matters if set per-frame (it is not).
- **Action:** Leave as-is; avoid setting it inside render loops.
- **Severity:** Low

## 10. Cross-cutting recommendations

1. **Establish an error-surfacing contract.** Every `catch` that today returns `[]` / `nil` / `false` should at minimum `Logger` the error, and user-impacting ones should set `PlayerState.statusMessage` (the existing channel). This directly fixes the §5 family — the same silent-failure pattern the Frame⁺ bundle bug exhibited.
2. **Propagate, don't swallow, GPU encoder failures.** Make `FramePlusMEMCEngine.encode*` throw so the pipeline can't silently degrade (§5.3/§5.4).
3. **Never ignore a `Bool` result from a file write.** `writeMirroredHLSPlaylist` results must be checked (§5.5/§5.8).
4. **Regenerate stale audit docs.** `AGENTS.md`'s S/D/DR tables are out of date; keep them in sync after cleanup to avoid re-doing work.
